# Changelog

All notable changes to CineSched are documented here.

## [Unreleased]
### Added
- **The Mac is a document-based app.** Each project is its own window, and the File menu is the system's: New Project (⌘N) opens an untitled window, Open (⌘O) and Open Recent are the Mac's own, and Save, Duplicate, Rename, Move To, Revert To (with Versions) and Close all work the way they do in every other document app. Projects autosave in place, so an edit survives quitting without pressing Save, and the window title shows the edited indicator. New projects save as `.cinesched`, which Finder now shows as "CineSched Project" and opens in CineSched on double-click. A legacy `.json` project still opens (File ▸ Open lists both types): its contents move straight into a new untitled window, so the first Save asks for a `.cinesched` destination and the `.json` is never touched. With two projects open, every File, Edit, Production and View command acts on the frontmost window, and each window keeps its own view (Calendar or Stripboard, cast row, times vs page counts, all days, grid vs list), which the next window opens with; a new "Schedule View" item in the View menu switches the frontmost window. Dark Mode and the theme remain app-wide. Undo and Redo in the Edit menu are the window's own and cover every edit: scenes and days, a call sheet, the production setup (including the cast roster), the project title, a production range change and the Shift Schedule toggle, each as one step (the sidebar and Production menu edits are labelled: "Undo Update Calendar", "Undo Edit Production Setup", "Undo Rename Project", …), and a drag of a strip and a burst of typing in the title field each undo as one step.
- **A native `.cinesched` file type.** The app now declares `com.lsvr.cinesched.project` (kind "CineSched Project", extension `.cinesched`, a JSON file inside) so that the iPad, iPhone and Vision Pro document browser shows only schedules rather than every `.json` on the device. It is the type every platform saves now (above and below); a `.cinesched` renamed to `.json` opens in every older build because the contents are identical. Under the hood, one shared project document (reading, writing and a whole-project undo that includes call sheets, production info and the title) is what every platform edits through.
- **Scene colors belong to the project.** The Customize Scene Colors palette is saved in the project file, so a schedule looks the same on every Mac that opens it and a PDF exported anywhere uses the same strip colors; each change in the editor is an undo step ("Undo Change Scene Color", "Undo Reset Scene Colors"), and Undo while the editor is open updates its swatches. A project saved before this build has no palette: the first time it opens on a Mac whose colors were customized it adopts that Mac's colors as its own (the board does not change color the day you update), and from then on the colors in the file win, whatever the device. The adopted colors are written to the file with the project's next edit. Older builds ignore the new `palette` field and open the file as before.
- **iPhone, iPad and Vision Pro open, create and autosave projects from a CineSched folder in iCloud Drive.** The same project builds for iOS, iPadOS and visionOS, and on those platforms the app is now "CineSched" with the system's document launch screen: New Project creates an untitled `.cinesched` in a CineSched folder that appears in iCloud Drive (in Finder on the Mac too) once the first project is saved there, Recents and Browse open any `.cinesched` in place (from Downloads or anywhere else in Files), and every edit autosaves without a Save button, so a change survives quitting the app and reaches the other devices signed into the account. The editor there is deliberately small for now, the project's title as a field and the shoot days with their scene counts; the real iPad, iPhone and Vision Pro editors follow (#1). Legacy `.json` projects do not open in place on those platforms; Import Project… on the launch screen (below) creates a `.cinesched` from one. These platforms need iOS, iPadOS or visionOS 27. The Mac app keeps its own file access with no iCloud entitlement, so building it from source needs no team membership; the first time the CineSched folder exists on a Mac, its Open and Save panels start there once, and from then on they remember the last folder used, as before.
- **A sync indicator beside the project title.** For a project in iCloud Drive (the CineSched folder, or any iCloud file opened in place), a small cloud symbol next to the title says whether this copy is Up to Date, Uploading, Downloading or Waiting for Network, on the Mac and on iPhone, iPad and Vision Pro alike; hover it for detail (an upload iCloud is retrying, say). A project outside iCloud, or one not yet saved, shows nothing there. The Mac reads the state from the file itself and needs no iCloud account of its own, only iCloud Drive; the indicator updates within a couple of seconds of a change.
- **A conflict notice with Restore Other Version.** When the same project was edited on two devices while one was offline, iPhone, iPad and Vision Pro keep the more recently edited version and the indicator reads "Conflict Resolved": its notice names the device and time of the version that was set aside, and Restore Other Version brings that version back as an ordinary edit, so Undo reverts the restore ("Undo Restore Other Version") and the resolution itself is an undo step too ("Undo Resolve Conflict"). Nothing is discarded silently: the set-aside version is kept for the rest of the session, the kept version's own copy in iCloud stays until the project file has been written with it (so quitting or a crash right after a resolution loses nothing; the next launch resolves it again), and the notice retires on its own after the next edit. The Mac keeps the system's own conflict dialog (the Versions browser) for choosing between versions; if a version chosen there, or one arriving from iCloud, replaces edits the Mac had not yet saved, the same notice appears with those edits restorable. Both need a project in iCloud Drive; there is nothing to resolve for a local file. On the iPad the notice's popover is sized for its wrapped message, so the title and the buttons are no longer cut off.
- **The iPad editor: three columns with an inspector.** In a regular-width window on iPad and Vision Pro a project now opens as the Mac's editor laid out for touch: the Boneyard sidebar (title, production range, New Scene, the sorted Boneyard) on the left, the calendar or Stripboard in the middle, and a trailing inspector on the right. The toolbar switches Calendar and Stripboard, undoes and redoes, holds a View menu (cast row, times instead of pages, all days on the Stripboard, Stripboard fields, color legend, scene colors) and a Production menu (Production Setup, Scan for Conflicts, Breakdown Browser, Lock and Unlock Schedule, Schedule Lock Report), and toggles the inspector; the system's sidebar button collapses and restores the sidebar, and both stay the way you left them for the next project. A single tap on a strip, on the calendar or the Stripboard or in the Boneyard, puts that scene's editor in the inspector, where Save Changes applies as one undo step; a single tap on a day cell, its date or a Stripboard day header puts the day's detail there (its statistics, day type and note, call sheet milestones, events with edit and delete, its scenes, Add Calendar Event, Edit Call Sheet, Export Call Sheet); the selected strip or day is outlined. A double tap on a strip opens the full editor sheet as on the Mac, and a long press on a strip, a day cell's header or an event chip shows the same menu the Mac's right-click does. Hovering a strip with a trackpad or a pointer shows its tooltip. In a compact window (an iPhone, a narrow Split View or Slide Over pane) the small title-and-days editor stands in until the iPhone companion lands. The sync indicator and the conflict notice sit in the toolbar. The Mac is unchanged.
- **PDF export with a preview and Share on the iPad and the Vision Pro.** Every PDF the Mac exports can now be exported from a regular-width window on iPad and Vision Pro: the toolbar's Export menu holds Schedule Calendar, Strip Schedule, Shooting Schedule (the whole schedule), Days Out of Days, Scene Breakdowns and, with a day selected in the inspector, that day's Call Sheet; the calendar's Export Month (PDF) button with its options dialog, the Stripboard day header's call sheet and shooting schedule buttons, the day inspector's Export Call Sheet and the call sheet editor's Export PDF all export too. Instead of a save panel the PDF opens in a page-sized preview with Done and a Share button; the share sheet offers AirDrop, Messages, Mail, Print, Save to Files, Markup, Copy and the rest, and the file arrives under the same name the Mac proposes (`The_Long_Way_Home_StripSchedule.pdf`, `CallSheet_Mon_Nov_2.pdf`, `Calendar_2026_11.pdf`). The bytes are the exporters' own, so a PDF exported on the iPad is identical to the Mac's for the same project and scene colors. The Mac keeps its save panels; the one change there is that an untitled project's shooting schedule is proposed as `Shooting_Schedule.pdf` instead of `Shooting_Schedule_Shooting_Schedule.pdf`.
- **Drag and drop by touch on the iPad, the same drags the Mac has.** Every drag on the board now works with a finger as well as a mouse: drag a scene from the Boneyard onto a calendar day or a Stripboard day, reorder a strip within its day, move a strip to another day, drag a strip back to the Boneyard, drag a day's grip handle to swap two days (scenes, call sheet, day type and note), and drag a day-type band (the "TRAVEL DAY" label in a calendar cell) to move just the type and note to another date, including onto a date outside the production range. A blue line shows exactly where a dropped strip will land, and every drag is one undo step. Under the hood the three old text encodings and the two drop delegates are gone, replaced by one typed drag payload, so a drop knows what it is carrying rather than parsing a string. Multi-selected strips still drag together (select with ⌘ or ⇧ on a Mac or with a trackpad or keyboard on iPad, then drag any one). The Mac's drags, including the previously fixed multi-select and gesture-priority cases, are unchanged, and drop highlighting clears after a drop and after Undo as before.
- **The iPad's menu bar, with the Mac's shortcuts.** On iPadOS 27 the app's menus are in the menu bar (revealed from the top of the screen, or with a hardware keyboard) beside the system's File and Edit items: New Project, Open, Save, Undo, Redo, Cut, Copy and Paste are the system's; Import Script and the four exports (Schedule ⌘E, Strip Schedule, Days Out of Days ⇧⌘E, Scene Breakdowns ⌥⌘E, each opening the preview with Share), the Production menu (Production Setup ⇧⌘P, Scan for Conflicts ⇧⌘K, Breakdown Browser ⇧⌘B, the hold-days toggle, Lock, Unlock and the Schedule Lock Report) and the View menu (Schedule View, the cast and time toggles, Theme, Color Legend ⇧⌘L, Customize Scene Colors, Stripboard Fields, All Days; Dark Mode stays the Mac's, the iPad follows the system) are CineSched's, and act on the frontmost project window; in a compact window they are disabled.
- **Copy, cut and paste scenes, on the Mac and the iPad.** Edit ▸ Copy (⌘C) puts the selected strips (the multi-selection on the board or in the Boneyard, or the scene the inspector shows) on the pasteboard; Edit ▸ Paste (⌘V) inserts them as new scenes right after the selected strip, at the end of the selected day, or into the Boneyard when nothing is selected, and selects what it pasted; Edit ▸ Cut (⌘X) copies and removes them as one step ("Undo Cut", "Undo Paste"). The copied scenes travel whole, so a paste into another open project, in a second window on the Mac or the iPad, inserts the same scenes there; pasting twice gives two scenes. A text field being edited keeps the three commands for its text, and a tap or click on a strip, a Boneyard row or a day hands them back to the board. Banners and calendar events copy and paste onto days but never into the Boneyard; the Stripboard's auto-meal strips are not copied.
- **An inactive window's board is dimmed on the iPad and the Vision Pro.** With two projects open side by side (Split View, Stage Manager), the calendar or Stripboard and the Boneyard of the window that is not active fade, so it is plain which project the keyboard and the pasteboard act on. The dimmed board still takes drops and taps. The Mac's windows look as before. (Before release the press recorder this shipped with, a gesture over the whole editor, had made every button in the iPad's toolbar and on the calendar dead to a finger; it is an observer now, and the toolbar's Undo and Redo also keep their enabled state in step with the edits.)
- **A trackpad or mouse on the iPad multi-selects like the Mac.** With a hardware keyboard and a pointer, ⌘-click adds a strip to the selection and ⇧-click selects a range, in the Boneyard and on the board, and the selection drags, copies and acts as a group; a finger or an Apple Pencil taps select one strip as before. The iPad now reads the modifier keys of a pointer's click, which it had no way to do.
- **The iPhone editor: a Days list, a week strip and a Day screen.** In a compact window (an iPhone, or a narrow iPad Split View or Slide Over pane) a project now opens as a tab view: Days, Boneyard, Production and Search, with the tab bar folding away as you scroll and a Today control above it. Days is the Stripboard as a scrolling list of day cards, driven by the same rows as the Mac's board: runs of empty days fold into one row that expands on a tap (and folds back from any of its days), a travel or other typed day is a tinted card with its badge and note, a day holding only a calendar event is a card too, and every card's header shows the production day number, the date, the scene count, the pages, the general call and the event count, with the day's event chips and its strips below, each strip timed by the same call-time cascade the Stripboard prints. A week strip above the list (Sunday first, the scene count under each date, typed days tinted, today ringed) scrolls the list to a date on a tap, pages by week, and its month title opens a calendar popover limited to the production range; Today lands on today's shoot day, or the next one, and reads which. Tapping a day's header opens the Day screen: the date and day number, the day type and note, a call sheet card (general call, ready to shoot, lunch, snack, dinner, wrap, basecamp), the calendar events and the strips. A long press on a strip previews the scene (number, slugline, pages, estimate, location, cast, summary) with an Open Day item. Everything is read-only for now; moving strips, editing days, the Boneyard, Production and Search tabs follow. Portrait and landscape both work (landscape keeps the week strip to one row), and the small title-and-days editor that stood in since the iCloud work is gone. The Mac and the regular-width iPad editor are unchanged.
- **The iPhone's Production tab: every Mac menu command on the phone.** In a compact window the Production tab lists, as rows of a grouped list, what the Mac's Production, View and File menus offer: Production Setup (the same form, with its cast, crew and location rosters; a character rename still reaches every scene and call sheet in one undo step), Scan for Conflicts (the count of conflicted scenes on the row, the report on a tap, and a row of the report switches to Days and scrolls to that date), Lock Schedule and Unlock Schedule (the row says when it was locked), the Schedule Lock Report (the number of changes on the row) and the Breakdown Browser, which opens the scene editor over every scene of the project in script order (12, 12A, 13 …) with Previous and Next, as on the Mac; Color Legend, Customize Scene Colors (each pick recolors the Days list at once, one undo step per color) and Stripboard Fields; the project's title (a burst of typing is one undo step), the production range with Shift Schedule and Update Calendar, which asks first when the new range would send scenes back to the Boneyard (the message says whether call sheets, calendar events, day types and notes stay on their dates or, with Shift Schedule on and the start moved, move with the schedule, exactly as on the Mac and the iPad) and applies as one undo step; the six PDF exports (Schedule Calendar, Month Calendar with a month to choose and the same options dialog, Strip Schedule, Shooting Schedule, Days Out of Days with the Include Hold Days toggle beside it, Scene Breakdowns), each opening the preview with Share, Print and Save to Files; and Import Script…, which picks a Fountain, Final Draft or Highland file, shows the summary (scenes, pages, cast, warnings) and adds the scenes to this project's Boneyard only on Add to Boneyard (Cancel leaves the project as it was). In a narrow iPad window the menu bar's shortcuts (⇧⌘P, ⇧⌘K, ⇧⌘B, ⇧⌘L, ⌘E and the rest) open the same rows' sheets from any tab. The Mac and the regular-width iPad editor are unchanged.
- **Move scenes from the iPhone.** The Days list and the Day screen now change where a scene sits. On the Day screen, Reorder in the Strips section turns on drag handles so a strip can be dragged to a new place in the day (its call times recompute as it lands); in the Days list a long‑press drag reorders a strip within its day the same way. Every strip carries a swipe (Next Day and Previous Day, Send to Day…, and for a script scene a Boneyard swipe that unschedules it) and a long‑press menu with the same items, so a slip to tomorrow is one gesture: Move to Next Day and Move to Previous Day drop the scene at the end of the adjacent day of the schedule (the next date on the board, whatever is on it; the first day offers no Previous and the last no Next), and Send to Day… opens a calendar limited to the shoot and drops the scene at the end of the day you pick. The Day screen's Add Scenes… (a row under the strips, and in the day's ⋯ menu) lists the Boneyard with checkboxes and adds every checked scene to the day in Boneyard order; Swap with Day (the day's ⋯ menu, and the Days‑list header's long‑press menu) exchanges everything two dates hold — scenes, call sheet, day type, day note and calendar events — while each keeps its own date. Each move is one undo step, reversible with a shake or the three‑finger swipe. (A strip cannot be dragged from one day's card into another in the Days list — iOS's list does not carry a drag across its sections — so Move to Next / Previous Day and Send to Day are the cross‑day moves.) The Mac and the regular‑width iPad editor are unchanged.
- **The iPhone's Boneyard and Search tabs, and a new scene from the phone.** The Boneyard tab lists every unscheduled scene as a strip, in the Mac's six sorts (Show Order, Default, Location, INT/EXT, Cast, Day/Night; the choice is the same preference the Mac's sidebar menu sets) with a filter field that narrows by number, slugline, cast, summary or real location as you type (every word must match somewhere; a number matches exactly or as a prefix, so "12" finds 12, 12A and 120), and a count of the scenes and pages listed. A tap opens the scene editor (Previous and Next step through the list, as on the Mac, and Duplicate Scene sits beside the trash); a long press is the Mac's Boneyard menu (Edit, Duplicate, Send to Day…, Delete) with the strip preview; the trailing swipe sends one scene to a day, duplicates it or deletes it (a duplicate is the Mac's copy: the title marked "(Copy)", the number, lengths, cast, summary and breakdown carried, the set and address left blank); a duplicate scene number wears the Mac's dashed red edge. Select turns on checkmarks for a multi-selection (with Select All) that one Send to Day… places on the chosen day, all of them, in the order the list shows them, as one undo step. "+" is the New Scene form: number, slugline, real location, pages, estimate and type; the estimate is derived from the pages when left blank (fifteen minutes an eighth, the Mac's rule), and the type's default reads the time of day off the slugline as you type it ("INT. KITCHEN - NIGHT" adds a night scene without a second tap; pick a type to override). The new scene lands in the Boneyard as one undo step and the list scrolls to it. The Search tab finds any scene, on any day or in the Boneyard, by number, slugline, cast (case-insensitive) or summary — never a banner, a meal strip or a calendar event — grouped into the scheduled results (each with its production day and date) and the Boneyard's: a tap opens the scene editor; the row's trailing button, its swipe and its long-press menu show the scene where it lives, Show in Days switching to the Days list scrolled to that day, Show in Boneyard switching to the Boneyard scrolled to the scene. The Mac and the regular-width iPad editor are unchanged.
- **Edit a day and its scenes from the iPhone.** Everything about a day is now editable from the Day screen and the Days list, each edit one undo step. A tap on a strip opens the scene editor, the same form the Mac and the iPad show, with every field including the breakdown tags; Save Changes shows in the list at once, Previous and Next step through the day's scenes, and Duplicate Scene sits beside the trash (the copy goes to the Boneyard, titled "(Copy)", as on the Mac). On the Day screen the day type is a menu and the day note a field (a burst of typing is one undo step), with Clear Day Type when either is set (a typed day outside the production range that then holds nothing disappears from the list, as it does on the Mac and the iPad); the call sheet card opens the call sheet form (general call, meals, wrap, basecamp, locations, cast calls, crew, notes), whose Save moves the call, meal and wrap strips with the times as one step, and an Export Call Sheet PDF row opens the preview with Share; the Calendar Events section adds an event, edits one on a tap and deletes one on a swipe; Add Banner… (a row under the strips, and in the day's ⋯ menu with Add Event… and Edit Call Sheet…) adds a company move, meal or notice strip, a tap on a banner edits it, and a swipe deletes it. Every action the Mac keeps behind a right-click has a home: a strip's long-press menu now offers Edit Scene (or Edit Banner), Set Time… (a fixed start and duration; on the lunch strip it moves the call sheet's lunch too), Duplicate Scene and Delete Banner beside Send to Day… and Return to Boneyard; the leading swipe is Edit and Set Time, the trailing swipe Boneyard, Send to Day and Duplicate (Delete on a banner); no swipe completes on its own, so a mis-swipe does nothing. The Days list's day header menu gains Edit Call Sheet…, Add Banner… and Add Event…, and its event chips open the event on a tap. The strips now print the fields the Production tab's Stripboard Fields picker turns on (cast names by default, the real location, props and the rest as chips), as the Mac's board does. The Set Time sheet is a grouped form on every platform now (on the Mac too: the same fields, Save disabled until a fixed time parses). The Mac and the regular-width iPad editor are otherwise unchanged.
- **Import Script and Import Project on the iPhone, iPad and Vision Pro launch screen.** Two new actions sit beside New Project (the launch screen shows two and folds the rest into More…). Import Script… picks a Fountain, Final Draft or Highland file from Files, shows the same summary the Mac shows (scene count, pages, cast, warnings) with a Create Project button, and creates a new project whose Boneyard holds the parsed scenes and whose title is the script's title page when it has one. Import Project… picks a legacy `.json` project and creates a new `.cinesched` with exactly its contents, older file shapes included. Either import lands as an untitled project in the CineSched folder, like New Project, and cancelling the file picker or the summary leaves nothing behind: no document, no file, no alert. The original script or `.json` is never modified. The Mac's File ▸ Import Script… still adds scenes to the open project as before.
- **Project files can carry shot lists and storyboard frames.** A scene can now hold an ordered list of shots (a description, a duration in minutes, equipment, props, SFX and one storyboard frame each) and a frame of its own; nothing in the app adds a shot yet (the scene editor's Shots section is next), but a project that has them opens, saves and prints them. Shots are lettered by position (12A, 12B …, and 12AA in scene 12A). While a scene has shots its estimated time is the sum of their durations, so the Stripboard's times, the day totals and every export follow the shot list. The scene breakdown sheet's Props, Special Equipment and SFX, and the Stripboard Fields chips for the same three, list the scene's own items followed by every shot's (a shot's equipment counts as Special Equipment), each once whatever its capitalization. Duplicate Scene and Copy, Cut and Paste of scenes carry the shots and frames, and the iPhone's Search and Boneyard filter also find a scene by what its shots say. Frames are stored inside the `.cinesched` file as JPEG. Project files are now written with their keys in a fixed order, so saving an unchanged project writes identical bytes (the contents are the same; older builds read them as before and ignore the shots).
- **The Shot List export.** File ▸ Export Shot List… on the Mac (also in the toolbar's Share menu, on the Mac and the iPad) and a Shot List row in the iPhone's Production tab first ask for the scope — the whole project, or one shoot day picked from the days that have scenes — and whether to include the storyboard frames; both choices are remembered for the next export. The document is portrait US Letter. With frames, each page holds three shots of equal height, the frame fitted whole into a box about 3.3 inches wide on the left (left empty when a shot has none) and the shot number, duration, description, equipment, props and SFX on the right; without frames, it is a table with one line per shot. Each day starts under its day number and date, each scene under its number, slugline, estimate and page count, and the whole-project list ends with the Boneyard in script order; a scene without shots prints as one entry under its bare number with its summary, estimate, breakdown items and frame. Banners, meals and calendar events are left out. The footer carries the project title, the scope and the page number. The file is named `<Project>_ShotList.pdf`, or `<Project>_ShotList_Day3.pdf` for one day; on the Mac it goes to the save panel and on the iPad, iPhone and Vision Pro to the preview with Share, like the other exports.

### Removed
- **The UserDefaults working copy, the current-file bookmark and the app's own Open Recent list.** The document infrastructure replaced all three. The first launch of this build recovers the working copy the previous build kept: if it is exactly what is in the project file you last saved or opened, that file opens (as a legacy `.json` always does now, into an untitled window that saves as `.cinesched`); if it holds edits you never saved to a file, or there was no file, it opens as an untitled project that asks where to save when closed. Either way the old copy is removed once it has opened, and the next launch is an ordinary one.
- **The "Clear All Scenes and Schedule?" prompt behind New Project.** New Project now opens a new window instead of clearing the current one.

### Changed
- **A cleaner Mac window toolbar.** The crowded row above the schedule is gone. The window's own toolbar now holds a centered Calendar / Stripboard switcher, a Share menu with every PDF export, and the search field. On the Stripboard it also holds a Display menu with Stripboard Fields and Show All Days. The schedule's figures (days, scenes done, time, scenes in the Boneyard) read as one line under the window title. The calendar's Export Month (PDF) button moved into Share ▸ Month Calendar, which opens the same options dialog with a Month picker (the months the shoot spans, starting on the current one); this is the same on the iPad, whose Export menu is now Share. On the iPad the Calendar / Stripboard switcher is a single control instead of a pill inside a pill. The calendar's Full Month / Full Schedule switch loses its emoji.
- **On the iPhone, a strip's trailing swipe is Boneyard, Next Day, Send to Day and Duplicate.** Previous Day left the swipe (five buttons made each too narrow to read on a phone row); Move to Previous Day is still in the strip's long-press menu.
- **The scene editor, the day detail, the banner input, the calendar event input and Send to Day are now forms, the same on every platform.** Each is one grouped form fitted to where it appears: the iPad's inspector column, a form-sized sheet on iPad and Vision Pro, a sheet with detents on iPhone, and the Mac's sheet at the size it had. Every field is still there. What changes on the Mac: the sheets are System Settings-style grouped forms (rounded sections on the window background, labels beside their fields) rather than free-standing fields with headings, so they look like the app's other 27-era controls; the scene editor's Type is a pop-up menu instead of six radio buttons, its Breakdown section folds and unfolds inside the form, and its Delete button is a red trash button at the left of the Cancel / Save row; the day detail's Add Calendar Event, Edit Call Sheet and Export Call Sheet (PDF) are rows under the day type and note rather than a button row across the bottom, its scenes are tinted rows you click anywhere to edit, and it closes with Done (the note is still saved on Return, on Done and when the sheet closes); the banner input's type is a pop-up menu rather than a segmented control, and switching it now renames a title you have not typed over (it used to rename only an empty one); the calendar event and Send to Day sheets keep their fields and their calendar. Saving the scene editor is one undo step on every platform (it used to be one only by the Mac's run-loop grouping), and its scene number, duration and estimated time now sit in labelled rows. The iPad's inspector column is 40 pt narrower (340 pt, from 380), which gives the calendar its Saturday and Sunday columns back on a 13-inch iPad; an inspector scene editor that you have not typed in follows the scene when an undo, a drag or a sync changes it.
- **Stripboard Fields, Customize Scene Colors, the Color Legend, the conflict report, the Schedule Lock Report, the script import summary and the Month PDF Options are now forms too, the same on every platform.** Each opens as a form-sized sheet on iPad and Vision Pro (from the toolbar's View and Production menus, the calendar's Export Month button and the launch screen's Import Script…) and as the Mac's sheet at the size it had. Every control and action is still there: the fields picker's switches still change the board behind it as they flip and its Reset to Default, Select All and Select None remain, the scene colors still write to the project as you pick (one undo step per color, Reset All to Defaults included), a conflict or lock-report row still jumps the schedule to its date, and the import summary keeps Done on the Mac and Cancel / Create Project on the launch screen. What changes on the Mac: they are grouped forms like the other editors, the fields and export options are switches in rows rather than checkboxes in boxes, the scene colors are one labelled color well per row instead of a two-column grid, the reports' empty states are the system's placeholder, the small × in each title bar is gone (Done, Close or Cancel does the same), and the Month PDF Options sheet is 40 pt wider. The Color Legend now draws its swatches from the project's palette, so a project with customized scene colors sees the colors its board shows rather than the standard code.
- **The call sheet editor and Production Setup are forms too, the same on every platform.** Both are grouped forms fitted to where they appear (a form-sized sheet on iPad and Vision Pro, a sheet with detents on iPhone, the Mac's sheet at the size it had: 780 × 750 and 620 × 720). Every field is still there. The call sheet's general call, estimated schedule, quote, ready-to-shoot, lunch, snack, dinner, wrap, hospital, weather, basecamp and notes are rows in labelled sections; the day's locations are a list with LOC numbers, Add from Roster and an add row; the cast calls and the crew calls are lists with one row per person (character, actor, scenes, status, the four times and the LOC number summarized on the row) that open a page for that person inside the editor, with a Back button in the editor's header, Remove and Done in its footer, and Add Cast Member / Add Crew Member rows that open a blank page (a row added there and left blank is dropped on Save; a blank row an older file already had is kept as it was). Auto-populate from Scenes, Load Crew from Setup and the pre-fills on opening (the production's default lunch, today's scene locations, the cast from the scenes, the crew from the setup) are unchanged, as is Export PDF (the Mac's save panel, the iPad's preview), and the Stripboard's call, meal and wrap strips still follow the times saved. Production Setup's company, the director, producer and 1st AD with their phones, and the cast, crew and location rosters are the same lists with a page per person: the cast member's page holds the actor and character names and the dates they are unavailable (add a From–To range, remove one), the crew member's the name, role, phone and Daily toggle, the location's the name and address; Pull from Breakdown is a row of the location roster. New in the setup: a Default Lunch Time field, which the call sheet editor already used as the lunch of a day that had none but which had no field before. Saving either editor is one undo step on every platform, and a character rename still propagates into every scene and call sheet within that step. What changes on the Mac: the six tabs of the call sheet editor are sections of one scrolling form; the cast and crew tables with a text field per cell are the row-and-page lists above; the roster's inline rows with a calendar popover per actor are the same lists, the unavailability now on the actor's page; the Daily checkbox is a switch on the crew member's page; and both sheets are System Settings-style grouped forms like the other editors.
- **Shrinking the production range returns the displaced scenes to the Boneyard in schedule order** (they used to arrive in an arbitrary order). Everything else about Update Calendar is unchanged.
- **Dragging a strip between calendar cells, Undo and Redo are quick again on a project of a few hundred scenes.** The document-based editor had made every drop and every undo redraw the calendar twice, and each redraw rebuilt the app's whole translation table once per menu item and tooltip it drew. On a 300-scene, 200-day project a drop or an undo now costs roughly 70 ms of main-thread time in a Release build, down from 105–110 ms on this branch and slightly better than the last released build (85–105 ms); the calendar no longer creates three date formatters per day cell, the conflict scan looks characters up in the cast roster instead of scanning it per scene, and a drag of strips between days is one edit rather than one per day in the range.
- **Opening a legacy project (the original scenes-and-days file) now resets the production info and created date** instead of keeping whichever project was open before. Loading goes through one decoder for every path; nothing else about loading or saving changes.
- **Strip schedule and shooting schedule PDFs no longer depend on AppKit.** They draw through a shared CoreGraphics/CoreText helper so they can later ship on iPad and iPhone. Page layout, fonts and colors are unchanged; the one visible difference is in lines cut off with "…": on the strip schedule they now use the same letter-spacing as the text around them (they used to be drawn slightly tighter) so a title or cast list may end one character sooner, and on the shooting schedule a title keeps one more character when it fits.
- **Month calendar and call sheet PDFs no longer depend on AppKit either.** Both pages of the month export and the call sheet now draw through the same helper. Layout, fonts (including the italic synopsis, quote and schedule lines) and colors are unchanged, pixel for pixel; as with the strip schedule, a line cut off with "…" (a cell's cast list, address or synopsis on the call sheet, an event chip in a month cell) may end one character sooner.
- **Breakdown sheets and the Days Out of Days no longer depend on AppKit, so no PDF export does.** Both draw through the same helper and are pixel-identical to before, including the breakdown sheet's auto-shrinking department lists. One deliberate change on the Days Out of Days: the blue, yellow and red status cells used to take their shade from the app's appearance (a touch lighter in dark mode); they are now always the light-appearance colors, so the PDF looks the same whatever theme the app is in.
- **Requires macOS 27; the new platforms require iOS 27, iPadOS 27 and visionOS 27.** The deployment floor moves from 26.5 to 27.0 on every platform in the project, the baseline the iPad, iPhone and Vision Pro work above is built on. Nothing about the Mac app's behavior changes.

### Fixed
- **Breakdown sheets print every scene's number.** The SCENE # cell read the number from the front of the scene's title only, which is where projects from before the scene-number field kept it; every imported and hand-entered scene since then keeps it in the field with a plain slugline, so the cell printed "—" for almost every sheet. It now prints the scene's number the way the shooting schedule does (the field first, a numbered title as the fallback), and only banners and calendar events, which have no number, still get a dash. The sheet-number cell's label is now "SHEET #": "BREAKDOWN SHEET #" was a point too wide for its column, so the "#" wrapped onto a line the cell clipped to a sliver. The masthead above still reads "BREAKDOWN SHEET"; nothing else on the sheet moves.
- **A call sheet longer than one page no longer loses everything after the first page.** A day with more scenes or cast calls than fit on one sheet used to export the right number of pages with every page after the first blank: the scenes table ran off the bottom of page 1, and the rest of the scenes, the cast and crew calls and the general notes were drawn below the edge of the pages that had been opened for them. Each table now breaks where the page ends and continues at the top of the next one, so nothing is left out. A call sheet that fits on one page is unchanged.
- **Shake to undo and the three-finger undo and redo gestures now work on the iPhone and the iPad.** A shake (or a three-finger swipe) used to do nothing in the iPhone editor and in the iPad's three-column editor unless a text field was being edited, and then it undid only the typing: the gestures ask UIKit's first responder for the undo manager, and a SwiftUI editor with no field focused had none, so the shake found the window's empty manager instead of the document's. The editor now keeps a first responder of its own behind the board that carries the document's undo manager and takes the status back whenever nothing else holds it (after a sheet, a menu or the undo alert itself closes), so a shake offers "Undo Move to Next Day", "Undo Set Day Type", "Undo Edit Call Sheet", "Undo Edit Scene" and the rest, a second shake offers the Redo, and a shake while typing in a field still undoes the typing alone. The Mac is unchanged: its window already answers Edit ▸ Undo.
